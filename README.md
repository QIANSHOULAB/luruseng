# 录入僧

施主去玩，贫僧填表。（2026-10-29 由「搬工」改名；旧的配置、名单、数据库、账本第一次打开时自动搬过来）

把一个文件夹里的刀具破损记录照片（照片、扫描件、HEIC 都行）送给 Gemini，认出每一条 TOOL BROKEN RECORD，边干边写进一本跟公司那本长得一样的 Excel。

- 下载：https://github.com/oilsongchengmin-svg/luruseng/releases/latest/download/luruseng.exe （双击就能用，不用装 Python）
- 用法：选文件夹，填钥匙（Google AI Studio 的 API Key，可以填两把），点「开始工作」。
- 来图就干（默认开着）：开机自己在后台挂着（窗口收在任务栏），往「待识别」放照片，30 秒内没再放新的就自己开工；自动开工的不弹 Excel 和核对窗口。认失败留在原地的照片不会被反复重试，等有新照片进来再一起干。点 × 只是收起窗口；真要退出，先去掉「来图就干」的勾。
- 自己换新版：把新版 exe 改名「录入僧.new.exe」放到 `录入僧.exe` 旁边，它会先试新版能不能打开，能就自己换上、重开，旧的更新包挪进 `F:\songchengmin\待删除`；记录在 `更新日志.txt`。不在干活的时候才换。
- 正名：要是从别名（比如「录入僧测试版.exe」）跑起来的，等 `录入僧.exe` 没人占着了，它会把自己抄回 `录入僧.exe` 再重开，别名 exe 挪进待删除。
- 只开一个：再双击图标只会把已经开着的窗口亮出来。`.录入僧状态.json` 写着版本、在不在干活、上一批结果（不含钥匙），给远程看。
- 每张认两遍对答案：第二遍用拉过对比度的图；两遍对得上就收，对不上认第三遍按多数定；几遍认得不一样的格子标红，O 列写明几遍各认成什么。一张照片 2～3 次请求。
- 认完先整理写法（不改内容）：零件号、机台去空格、统一横杠；描述开头混进去的刀号（T44 …）挪回 T NO.，几把刀写成「T6, T7」；ø、⌀ 等统一成 Φ；班次「白/夜/Day/Night」统一成 D/N。
- 设计记录（每一步为什么这么定）：`docs/设计记录.md`
- 编号：照片按拍摄时间（EXIF，没有就用文件时间）编号 1、2、3……，表里 A 列 No. 就是照片编号：第 N 张照片的记录在 No. N 那一行。一张照片有两条记录就两行同一个编号；认不出、失败的也留一行，编号不会错位。
- 编号照片：认完以后，在每张照片最空的那个角印上大红编号（白底红框；四个角都有字就在顶上加一条白边写），存成 `已识别\<这次的时间>\01.jpg、02.jpg……`，干完跟 Excel 一起自动打开，人对着核。送去识别的永远是原图，编号不会被当成内容。原图原封不动放在同一个文件夹的 `原图\` 里。
- 核对：主窗口的「核对」按钮（每批干完也会自动弹出）打开核对窗口：左边是编号照片，第一张就是 1；「上一张 / 下一张」或键盘 ←→ 翻页，输入编号回车直接跳；右边列出表里同一号的记录，标红的字段在这里也是红的；双击照片用系统看图打开原尺寸。顶上可以换看以前的批次。
- 数据库（越认越准）：主窗口「投喂数据」选公司的 TOOL BROKEN RECORD（可多选；核对过的录入僧结果表也行），每一页的记录和 NAME 页的工号名字都吃进 `录入僧.exe` 旁边的 `数据库.sqlite`；或者把表丢进旁边的 `投喂\` 文件夹，每次开工前自动吃（改过的会重吃，同一条记录不会重复）。识别时以数据库为准：出现过的机台、零件号、刀具描述随请求告诉模型；认出来的值跟库里的只差一个容易看错的字（O/0、I/1、S/5、B/8…）就改成库里的写法，标橙；库里没见过的机台、刀具描述，模型认得清就不标，拿不准才标红（没见过的零件不标，新零件常有）。不按零件对历史（零件、刀、MO 之间的老关系不拿来标红）。录入僧自己认出来的不进库，只认喂进去的表。数字和日期每次都是新的，靠 PASSED+FAILED=TOTAL 这类检查兜底。数据库只在本机，不上 GitHub。命令行：`录入僧.exe --feed 表.xlsx`。
- 名单：`录入僧.exe` 旁边的 `名单.txt`，一行一个「工号/名字」（记事本就能改）。有名单时：名单会告诉模型；单子上只写工号、只写名字、或者写得潦草，SETTER 按名单补成完整的「工号/名字」；工号和名字跟名单对不上的标红；不在名单里的新人，认得清就不标。名单不进 GitHub。
- 表格：B 到 N 列跟公司 TOOL BROKEN RECORD 一格不差（DATE、MACHINE、PART NUMBER、MO、OPR NO.、T NO.、DESCRIPTION、BTMP、TOTAL SCREENED、PASSED、FAILED、SHIFT、SETTER），复制 B 到 N 的数据行整块贴进公司表。O 列是核对提示，不用贴。
- 标红（只标拿不准的，认得清的不标）：模型自己说拿不准的字段（每条记录多回一项 unsure）、有看不清的字（□）、数字不是数字、SHIFT 不是 D/N、PASSED + FAILED ≠ TOTAL SCREENED。日期从不标红（错了无所谓），认不出就照原样写。只看红格子就行。
- 日期：新加坡写法日在前；年份一律按今年（认成别的年份也改成今年）；日期从不标红。
- 每批 5 张，每张单独一次请求，5 张同时发；每批干完存一次盘。
- 这一批的编号照片和原图在 `已识别\<这次的时间>\`，跟 `识别结果\识别结果_<这次的时间>.xlsx` 一一对应。失败的留在原地，下次点开始会重试。日志在 `识别结果\录入僧日志.txt`。
- 干过的照片记在账本里（按文件内容算指纹），改了名也不会重干，会挪进 `已识别\重复\`。
- 每分钟次数到顶：按谷歌回的 retryDelay 等（没给就等 60 秒）接着干。当天额度用完：先换钥匙 2；两把都用完就等到太平洋时间半夜（新加坡下午 3 点，冬令时 4 点）额度刷新后接着干。
- 谷歌说预付余额用完、钥匙无效、模型不存在：直接停，把谷歌原话写进日志。
- 钥匙只存在本机 `%APPDATA%\录入僧\config.json`，请求时只走 URL 参数 `?key=`。
- 无窗口跑一轮：`录入僧.exe --cli [文件夹]`（读同一份配置）。
