# 录入僧（原名搬工）· 设计记录

> 2026-10-29 晚改名「录入僧」，副标题「施主去玩，贫僧填表」。Song 嫌「搬工」难听；挑名字时给了两轮候选（判官笔、照妖镜、抄单侠、鬼画符翻译官；字迹收容所、录入僧、单子粉碎机、纸上谈兵、抄经人、刀簿、墨鬼），他选了录入僧、自己配了副标题。改名不丢东西：旧配置、旧账本、旧文件夹里的名单/数据库/投喂/照片在新版第一次打开时自动搬过来，旧文件夹和旧快捷方式挪进「待删除」。下文保留当时的叫法。

手写单子照片 → 公司 TOOL BROKEN RECORD 格式的 Excel。2026-10-29 一天从网页版做到桌面版 v1.5.3，这份记录写的是每一步为什么这么定，留给以后做同类东西时照着走。

- 代码：https://github.com/QIANSHOULAB/luruseng （打包好的 exe 在 Releases，`releases/latest/download/luruseng.exe`）
- 前身网页版：https://qianshoulab.github.io/songm/ （仓库 QIANSHOULAB/songm）

## 一句话说清楚它干什么

照片丢进文件夹，点「开始工作」。每张照片单独发一次 Gemini，按公司表的 13 列认出每条刀具破损记录，边干边写 Excel；照片按拍摄时间编号，编号印在照片空角上，跟表里的 No. 对上；只有拿不准的格子标红；喂进公司的历史表当准绳，用得越多越准。干完自己停。

## 从网页到桌面：每一步改了什么、为什么

**网页版 songm（单个 HTML，GitHub Pages）。** 起点是一次把多张图塞进一个请求，钥匙存在浏览器里，六种导出。

**手机上跑不通。** 原因是 Gemini 2.5 系列对新申请的钥匙不开放，偏偏页面把谷歌的报错改写成了自己编的话，排查方向被带偏。从此定规矩：钥匙只走 URL 参数 `?key=`，不用请求头；报错原样显示 HTTP 状态码加谷歌返回的原话，不翻译、不改写。默认模型换成 `gemini-3.5-flash-lite`。

**认不准。** 图片压到 1024 像素太糊，多张图放一个请求会串行。改成长边 2048、JPEG 质量 0.92，每张照片单独一次请求。

**只抓手写、每批 5/10 张、第二把钥匙。** 第一把额度用完自动换第二把。

**弄清额度。** 额度按请求次数算，跟图片大小无关；3.5 Flash-Lite 免费档每天 500 次；每天的额度在太平洋时间半夜刷新，即新加坡下午 3 点（11 月到 3 月是 4 点）；AI Studio 速率页上的数字是一段时间内的峰值，不是实时用量。

**要不要把几张图打包成一个请求省额度。** 讨论过 2 张、5 张一包。一个请求里放多张图，就没法保证不串味，只能压低概率。算账：一张一次，每天 500 次，一天能跑 50 批 10 张，用不完。放弃打包，保持一张一次。

**搬工：桌面全自动版。** Song 要的：指定文件夹，5 张一批，干过的不重干，额度用完就等，干完就停，只要 Excel，点「开始工作」开干。

**格式改成公司的 TOOL BROKEN RECORD。** 13 列一格不差，A 列加照片编号 No.，复制 B 到 N 就能整块贴进公司表。

**照片编号。** 先说编号对行号；再要求编号直接写在照片上（「电脑好认，人不好核对」）；再要一个核对窗口，一张张翻、输入编号直接跳。

**越认越准。** Song 的想法：人名工号、机台、刀就那么几个，认多了统计就知道。最后定的做法是投喂公司的历史表当数据库，以它为准。

**收紧标红。** 去掉按零件对历史的检查和「没见过的零件」；改成只标拿不准的；日期从不标红；年份一律按今年。

## Song 定下的规矩（同类产品默认照办）

- 钥匙只走 URL 参数 `?key=`；报错原样显示，不编、不改写。
- 准确第一：一张照片一次请求，不打包。
- 只出 Excel，格式跟公司表一格不差，直接能贴。
- 照片编号就是表里的 No.，编号印在照片空角上；认完才印，送去识别的永远是原图。
- 只标拿不准的，认得清的不标。日期从不标红，年份一律按今年，认成 1998 也改成今年。
- 数据库以喂进去的公司表为准；搬工自己认出来的不进库。
- 不按零件对历史：零件加刀对描述、MO 对零件、零件对工序，都不拿来标红；没见过的零件不标红，新零件常有。
- 名单、数据库是同事和公司的数据，只放本机，不进 GitHub。
- 先谈方案、拍板后再做；拍板题编号、每题 A/B，他按顺序回字母（如 "abbb"）。
- 能自动的都自动，他只做一次性的事（贴一次钥匙、拷一次公司表）。

## 架构

**技术栈。** Python 3.12，Tkinter 窗口，Pillow + pillow-heif（iPhone 的 HEIC），openpyxl 写 Excel，sqlite3 做数据库，pywin32 建快捷方式。PyInstaller 打成单个 exe。GitHub Actions 在 Windows 机器上跑全部测试、打包、用假谷歌真跑一遍 exe、喂一次假的公司表、建快捷方式，全过了才发 Release。

**文件放哪。**

| 位置 | 是什么 |
|---|---|
| `搬工.exe` 旁边的 `名单.txt` | 一行一个「工号/名字」，记事本能改 |
| `搬工.exe` 旁边的 `数据库.sqlite` | 喂进去的公司记录（records / people / sources 三张表） |
| `搬工.exe` 旁边的 `投喂\` | 丢进去的表每次开工前自动吃，改过的重吃 |
| `待识别\` | 照片放这里 |
| `待识别\识别结果\识别结果_日期_时间.xlsx` | 每批一本新表 |
| `待识别\识别结果\搬工日志.txt`、`.搬工账本.json` | 日志；账本按文件内容指纹记干过的照片 |
| `待识别\已识别\日期_时间\01.jpg…` | 印了编号的照片；原图在同目录 `原图\01_xxx.jpg` |
| `%APPDATA%\搬工\config.json` | 文件夹、两把钥匙、模型（只在本机） |

**一张照片走一遍的流程。** 扫文件夹，按 EXIF 拍摄时间排序编号（没有 EXIF 用文件时间）→ 查账本，干过的挪进 `已识别\重复\` → 5 张同时发，每张一次请求：EXIF 转正、长边 2048、JPEG 0.92 → 提示词写清 13 个字段的样子（机台像 VM-07、4X-9；MO 是 8 位数；SHIFT 只有 D/N…），附上名单和数据库里出现过的值 → `responseSchema` 规定输出 `records` 数组，每条 13 个字段加一个 `unsure`（模型自己拿不准的字段名）→ 解析 → 数据库纠正 → 名单匹配 → 标色 → 每批 5 张存一次 Excel → 印编号 → 原图归档 → 记账本。

**额度和出错。**

| 情况 | 做法 |
|---|---|
| 429，每分钟到顶 | 这把钥匙停 60 秒，有第二把先用第二把 |
| 429，当天用完 | 这把钥匙停到太平洋时间半夜；两把都完就睡到刷新再接着干 |
| 429，预付余额用完（prepayment credits depleted） | 直接停，等也没用 |
| 400 钥匙无效 / 404 模型不存在 | 直接停，原话写进日志 |
| 400 不认结构化格式 | 去掉 responseSchema，改纯 JSON 提示重试 |
| 5xx、断网 | 10、30、60 秒后重试三次 |
| 模型回的不是 JSON | 这张算失败，照片留在原地，下次再干 |
| 手动停 | 没干完的在表里留灰色一行，下次接着干 |

**其他防坑。** Excel 开着导致存不了盘时另存一份；去掉 Excel 不认的控制字符；`=` 开头的值按文字存，不当公式；Gemini 3 起不再发 temperature（官方已废弃，以后会报 400），只给 2.x 模型发。

## 标色规则（最终版）

| 颜色 | 什么时候 |
|---|---|
| 红 | 模型自己说拿不准；有看不清的字（□）；该是数字不是数字；SHIFT 不是 D/N；PASSED + FAILED ≠ TOTAL；工号和名字跟名单对不上；库里没见过、模型又拿不准的机台或刀具描述 |
| 橙 | 按数据库改过：跟库里某个值只差易混字（O/0、I/1、S/5、B/8、Z/2、G/6），或只差一个字且库里出现过两次以上 |
| 黄 | BTMP 列，跟公司表一样 |
| 灰 | 中途停了没干完的那张 |
| 不标 | 日期（任何情况）；认得清的新机台、新刀、新人、新零件 |

O 列「核对提示」写明每个红格、橙格的原因，不用贴进公司表。

## 踩过的坑

- 自己编的报错文字把人带偏，比没有报错还糟。报错一律原样显示。
- Gemini 2.5 系列只对以前用过的账号开放，新钥匙要用 3.5 Flash-Lite 或 3.8 Flash。
- AI Studio 顶上「预付余额已用完」的提示：论坛有人报告会连累同账号的免费项目，返回 429 "Your prepayment credits are depleted"。
- WScript.Shell 建快捷方式，中文文件名会变问号；改用 Unicode 版 IShellLink（pywin32）。PowerShell 5.1 读中文脚本要带 BOM。
- 给 Windows 记事本看的文本文件：UTF-8 带 BOM、CRLF 换行。
- 公开仓库里放过截图上同事的真名当测试数据，后来全换成编的名字。真名单只能放本机。
- 沙盒连不上谷歌，钥匙也不能由 AI 代填，所以测试全靠假谷歌服务器；真单子的识别效果要等第一批真跑。
- 用户中途会改主意（去掉按零件查历史、日期规则）：功能拆小、每次改完马上测完整套、马上装，改起来就快。

## 下次做同类工具的检查清单

- 先拿一张真单子和一张目标表的照片，把输出格式定死：列名、列顺序、日期写法、哪列要能直接粘贴。
- 先查清额度：按请求还是按 token 计、每天多少、几点刷新、超了回什么错。
- 准确优先就一张一次请求；额度紧了再谈打包，先算每天真实用量。
- 输出加编号，编号同时出现在表里和原件上，人才对得上。
- 只标拿不准的：让模型自己报 unsure，再加几条硬检查（加总对不上、该是数字的不是数字）。
- 有历史数据就做投喂：只认人核对过的表，认出来的不自动进库。
- 报错原样显示；钥匙只存本机；同事和公司数据不进公开仓库。
- 测试先用假服务器把出错路径全跑一遍（额度、断网、钥匙无效、坏 JSON、中途停）。
- Windows 上发 exe：GitHub Actions 打包加冒烟测试，过了才发布；装的时候顺手建桌面快捷方式。

## 第一次真跑（2026-10-30 早上，v1.6 旧版）和 v1.7 的改法

**拿什么测。** Song 拍的 3 张真单子（不是登记表，是「TOOL REQUEST FORM 换刀调试单」，一张一条记录），加 40 张照着真单子样子造的假单子（手写体字体一个字一个字抖着写、横着拍、加噪点和阴影），每张都有标准答案。假单子比真的干净，分数只当相对比较用。

**结果。** 43 张全成功，2 分 32 秒，51 次请求。谷歌免费档每分钟上限撞了两次，每次自己等 60 秒接着干，一张没丢。硬数据（机台、MO、步骤、数量、工号）全对；按格子算 95%。毛病集中在：班次没圈也硬猜（43 格错 11 格）、一张写两把刀时第二个刀号混进描述、Φ 被吃掉、零件号中间多空格。更要命的是错的格子几乎都没标红：模型很少说自己拿不准。

**v1.7 怎么改。**
- 每张认两遍对答案，对不上认第三遍按多数定，几遍不一样的格子标红。模型的自我报告（unsure）靠不住，两遍对答案才是真正的「拿不准」信号。代价是请求翻倍（一天 500 次免费额度 ≈ 200 来张），准确第一。
- 认完先整理写法：零件号去空格、刀号从描述里挪回来、Φ 统一、班次统一成 D/N。能用规则修的不靠模型。
- 提示词：班次只认手写记号，没标就空；所有 T 加数字都是刀号；Φ 一定照写。
- 自动驾驶：开机后台挂着、来图就干、丢「录入僧.new.exe」自己换新版、只开一个。原因：人不在电脑前时，远程既点不了窗口（最前面挡着别的窗口），程序开着又换不了 exe。

**v1.7 复测（同样 43 张，换了文件指纹重放，2026-10-30 06:55，来图就干自己开工）。**

| | v1.6（旧） | v1.7 |
|---|---|---|
| 按格子算对 | 95.1% | 99.0% |
| 整行全对 | 22 / 43 | 38 / 43 |
| 错的格子 | 25 | 5 |
| 错的格子里标了红的 | 0 | 4 |
| 红格子总数 | 0 | 9（4 个真错，5 个其实对） |
| 请求次数 / 用时 | 51 / 2分32秒 | 100 / 6分21秒 |

3 张真单子：班次「白」认成 D 了，Φ 保住了，两把刀分开了。剩下的问题：第 3 张零件号三遍认成三个样（AB-3067282E / AB-3A67282C / AB-5067282E），用了第一遍的、标红；那个「5」手写得像「3」，人看也得想一下。唯一没标红的错：一张假单子班次没标，两遍都猜成 N。

**远程换版也真跑通了。** v1.7.0 → v1.7.1：放下「录入僧.new.exe」，等它闲下来自己试新版、自己换、3 秒重开。第一次装 v1.7 时 `录入僧.exe` 被一个看不见的旧进程占着，只能先装成「录入僧测试版.exe」，所以 v1.7.1 加了「正名」：等 `录入僧.exe` 没人占着了自己抄回去。

## 苹果风外观（v1.7.4–v1.7.5）和通用版（v1.8，2026-10-30）

**外观。** Song 拿 Mac 的界面当样子，自己出了定稿图：左边一张大卡片放设置和按钮（按钮带图标，「开始工作」是唯一的蓝色按钮），右边「任务状态」大字（数字蓝色），日志单独一张卡片，「来图就干」是方形勾选框。Tk 自己画圆角有锯齿，所以圆角、图标、开关都用 Pillow 放大 4 倍画好再缩小（`bangong/macui.py`）。标题栏保留 Windows 自带的：假的红黄绿三个点得拆掉系统标题栏，「× 收起、后台照样盯着」就坏了。**Song 定的底线：以后任何产品的界面最差也要这个水准。**

**通用版：只出一个版本。** 准备给别人用时 Song 说「几个版本麻烦」：所有人用同一个 exe。
- 分辨老用户靠这台电脑上有没有录入僧的设置文件：有（Song 自己的电脑）→ 所有开关全开、什么都不变；没有（新装）→ 对新人客气的默认值（`bangong/settings.py`）。
- 文件位置跟着 exe 走，不写死任何人的路径：exe 放哪，「待识别」「投喂」、数据库就在哪。Song 的原话：「别人选保存哪里默认就变哪里，和我们的不冲突，我们只是选了 F 盘」。要扔的东西挪进「待删除」：上一级有「待删除」就用（Song 的 `F:\songchengmin\待删除`），没有就在程序文件夹里建。
- 直接在「下载」里双击：在旁边建「录入僧」文件夹，把自己抄进去再从那里开（家里已经有一样新的就直接开家里那个），东西不撒一地。
- 右上角 ⚙ 设置，七个拨动开关：开机自动启动、点 × 只收起、干完自动打开、保留原图（关了原片进回收站）、自动更新、记住钥匙、桌面和开始菜单图标。来图就干留在主窗口。新装默认：开机启动关、× 直接退出、来图就干不勾，其余开。
- 自动更新：每次发版 Release 里多放一个 `version.txt`；程序每 6 小时去 `releases/latest/download/version.txt` 看一眼，比自己新就把 `luruseng.exe` 下载成「录入僧.new.exe」，再走原来那套「先试能不能打开、再换、重开」。只在空闲时换：没在干活、没在核对、没在投喂、没开设置、两分钟没人碰。换失败的版本这次开着就不再下。只有改了 `VERSION` 才算新版，推代码不改版本号不会惊动别人。
- 网站：<https://qianshoulab.github.io/luruseng/>（仓库根目录的 `index.html`，GitHub Pages）。Song 把网址发给别人，点一下就下载；网页上写了怎么申请钥匙、浏览器「不常下载」和 Windows 蓝框「已保护你的电脑」该点哪里、照片会发给谷歌认、表格数据只在自己电脑上。手机打开会提示「这是电脑程序」并给「复制网址」。只改网站或说明不重新打包。

## 类别：刀单以外的单子（v1.9，2026-10-30）

**Song 的要求。** 刀单有专属优化，别的单子也要各有各的；认别的单子学到的东西不能跑进刀单。别人可以自己加类别：建了就有独立的文件，把认完改对的表放进去，就成了这个类别的专属数据库。「放入数据库」要能选放进刀单还是放进哪个自建类别。

**拍板（Song：Aa）。**
- 新类别还没放过表时：先「认全部内容」，模型拿单子上印好的栏目名当列名出一本表；改对了放进数据库，表头就定成这个类别的列（不用人打列名）。
- 认的时候：主窗口加「类别」下拉框，选哪个按哪个认（没选「每个类别一个待识别子文件夹」那个方案）。

**怎么做的（`bangong/tables.py`）。**
- 刀单那套原样不动：Engine 不传 `spec` 就是刀单。自建类别传一个 `TableSpec`，它管提示词、解析、整理、两遍对答案和出表。
- 每个类别一个文件夹 `类别\<名字>\`：`数据库.sqlite`（列、记录、吃过的表）和 `投喂\`（丢表进去，每次开工前自动吃）。
- 认全部内容：提示词让模型输出 `columns` + 每条记录的 `values`；几张照片、几遍的列名按「大小写、空格、标点不算」统一成第一次见到的写法。表每次存盘整本重写，新冒出来的列接在右边。
- 定了列以后：列编成 c1…cN 给模型填（结构化输出），每列「例如」后面放库里出现过的值；来回就那几个值的列（重复出现、不是数字和日期、不是长句子）按库纠错，跟刀单同一招；数字列只收数字；表头带「日期/时间/date」的列从不标红（跟刀单一样）；几行改对过的记录放进提示词当例子。
- 互不串味：刀单的库只吃像刀单的表（找不到 DATE、MACHINE 表头就整本不吃，别的页上的工号名字也不读）；自建类别各用各的库文件。
- 核对窗口按表头排列：刀单那本照旧，自建类别的表第 2 行是表头。
- 放入数据库是一张小卡片：先选类别（可以当场「＋ 新建类别」），再选表。中文说明用按字折行的文本框（Tk 的 Label 只在空格处折行，中文会折得乱七八糟）。
